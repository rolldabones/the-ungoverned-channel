| Q1 | What happens to channel memory when the agent is removed from a channel, and when the integration is terminated? Deleted, retained, retained-with-TTL? **Resolved 15 Oct 2026:** `/remove @Claude` deletes nothing; memory, routines and past sessions stay and re-adding picks them up. Deletion happens on an Owner's **Remove this scope** (that channel's sessions, transcripts, memory, routines, artifacts), on workspace disconnect or app uninstall (everything for the workspace) and on Slack channel deletion. Turning Claude off deletes nothing. Backups age out after a limited period | C6 (rehearsed Exit) is blocking without this; discovery and GDPR analysis in `07`/`08` both hinge on it. C6 can now be rehearsed against documented behavior; C7 is rebuilt | Vendor documentation: data-lifecycle page |
| Q2 | What is the retention period and export capability for the centralized audit console? ~~Resolved~~ **Partly resolved 15 Oct 2026, adversely** [re-marked 20 Oct 2026: the answer below covers transcripts and memory, not the activity log]: during the beta there is no automatic retention period for transcripts or memory, the organization's custom retention setting does not apply to them, session transcripts and memory are not included in the organization's data exports and the Compliance API does not list or delete Claude Tag sessions; workspace disconnects and scope removals are written to the audit log the Compliance API reads. **Still Unknown:** the retention period and export capability of the activity log itself (who requested, which tools were used) | C10; regulated-records deployers cannot rely on logs they cannot produce. For transcripts and memory, retention is indefinite and export is absent, which is worse than a short period would have been; C10 (`09`) rests on the activity-log Unknown | Vendor documentation: data-lifecycle page |
| Q3 | Do externally shared (Slack Connect) channels interact with channel memory or cross-channel learning in any way, even when the agent is not a member of the shared channel? **Narrowed 20 Oct 2026:** by default Claude is off in Slack Connect channels and a mention there gets no reply, until an Owner or Claude Tag admin turns it on for a channel, a workspace or all of Slack; in a channel shared across workspaces connected to different Claude organizations Claude does not reply and posts a refusal; in a channel shared across workspaces of one Claude organization the repositories, instructions and memory set up for that channel or its workspaces do not apply (`13` item 33). Still Unknown: whether Slack Connect content reaches channel memory or cross-channel learning where Claude is not a member | Determines whether C3's Slack Connect exclusion is sufficient or merely necessary | Vendor documentation or security research |
| Q4 | Is ambient mode off by default at the organization level, and is the toggle per-channel or global? **Resolved 15 Oct 2026:** **Respond automatically** is on by default; each channel has its own copy and there is no workspace- or organization-wide version; any channel member can change it by asking Claude unless an Owner sets **Channel member edits** to Block | C2's cost depends on granularity; per-channel means C2 is executable but must be executed once per channel and locked | Vendor documentation: when-claude-responds page |
| Q5 | Can channel memory be enumerated, inspected or selectively corrected by an admin? **Resolved 15 Oct 2026:** yes. An Owner opens **View memory files** on a workspace's or channel's page, picks a file and deletes it or an entry; anyone in the channel can tell Claude to forget an entry. Earlier versions of the scope's memory remain stored until the scope's data is deleted, so correction is prospective, not erasure | Row 2 of the ledger; GDPR rectification and erasure; P2 (scored) | Vendor documentation: data-lifecycle page |
